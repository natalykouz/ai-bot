# Деплой ai_bot на прод-сервер компании

Инструкция для того, кто разворачивает бота на боевом сервере. Сейчас бот развёрнут
и проверен на Railway (тестовый бот) — здесь описано, что нужно повторить на другой
инфраструктуре.

---

## 1. Запуск

- Python 3.13, зависимости — `pip install -r requirements.txt`.
- Точка входа: `python main.py`. Это долгоживущий процесс (polling к Telegram API),
  входящий порт/webhook не нужен — процесс просто должен быть постоянно запущен
  и автоматически перезапускаться при падении.

## 2. Persistent-хранилище — обязательно

Папка `prompts/` должна быть смонтирована как **постоянный диск/volume**, который
переживает перезапуски и редеплои.

Причина: в этой папке лежат не только тексты промптов (их можно поменять из Telegram
командой `/setprompt` без редеплоя), но и файл `prompts/auth.json` — в нём хранится
хеш пароля доступа к боту и список ID пользователей/админов. Если папка не примонтирована
как постоянный диск — при каждом перезапуске пароль и список пользователей будут
сбрасываться к значениям по умолчанию из переменных окружения.

## 3. Переменные окружения

| Переменная       | Назначение                                                                 |
|------------------|-----------------------------------------------------------------------------|
| `BOT_TOKEN`      | Токен прод-бота в Telegram (от @BotFather)                                  |
| `OPENAI_API_KEY` | Ключ OpenAI API для прода                                                   |
| `OPENAI_MODEL`   | Модель по умолчанию (fallback), сейчас используется `gpt-4o-mini`           |
| `ADMIN_IDS`      | Telegram user_id админов через запятую, напр. `111111111,222222222`        |
| `BOT_PASSWORD`   | Начальный пароль доступа — используется один раз, при первом запуске        |

`ADMIN_IDS` и `BOT_PASSWORD` читаются только при первом запуске, когда ещё нет файла
`prompts/auth.json` — дальше это состояние живёт в самом файле и меняется только
через команду `/setpassword` в боте (см. README.md, раздел «Доступ по паролю»).

## 4. Какие данные нужно получить и как их передать

Нужно от меня (или от того, кто выпускает прод-креды):

- `BOT_TOKEN` — **рекомендую завести новый бот** через @BotFather специально для прода,
  а не переиспользовать токен тестового бота. Так проще разграничить доступы и не
  перепутать тестовый/боевой чат.
- `OPENAI_API_KEY` — по возможности отдельный ключ/проект в OpenAI для прода
  (легче отслеживать расход и отозвать при необходимости, не затрагивая тест).
- `ADMIN_IDS` — список Telegram ID реальных админов прод-бота.
- `BOT_PASSWORD` — стартовый пароль. После первого успешного запуска и проверки
  **сразу смените его** через `/setpassword` в самом боте — значение из `.env`/переменных
  окружения не должно оставаться постоянным паролем.

**Как передавать:** это чувствительные данные (токен, ключ API, пароль) — их не стоит
пересылать тем же каналом, что и эту инструкцию (например, одним и тем же письмом или
сообщением в общем чате). Используйте:
- корпоративный менеджер паролей (1Password, Bitwarden и т.п.) с доступом только у
  нужного человека, или
- одноразовую защищённую ссылку (1Password/Bitwarden Send, или аналог), которая
  становится недействительной после просмотра.

После деплоя старые значения (если передавались через временный канал) стоит удалить/
инвалидировать.

## 5. Проверка после деплоя

1. `/start` от аккаунта из `ADMIN_IDS` — должно показать «Вы являетесь администратором
   бота» и список админ-команд.
2. `/start` от любого другого аккаунта — должен запросить пароль; неверный пароль
   отклоняется, верный — открывает доступ.
3. Перезапустить процесс (или передеплоить) и убедиться, что уже допущенный пользователь
   не должен вводить пароль повторно, а `/setpassword`-изменения (если применялись)
   сохранились — это подтверждает, что `prompts/` примонтирована как persistent volume,
   а не как временная папка контейнера.
