# COMPONENT_UI.md

Справочник UI-логики заполнения компонентов для СММ-менеджера в Telegram-боте:
**название компонента → превью → какие понятные поля показать менеджеру → в каком порядке их спросить.**

Источники (только текущее состояние, без git-истории и архивов):
`mail_project/catalog.html` (визуальный каталог, 122 компонента, атрибуты `letteros-element`/`letteros-module`/`letteros-hide` — это внутренние семантические подписи полей, зашитые в саму библиотеку компонентов),
`mail_project/manifest.json` (122 записи: `module`, `element`, `sample_text`),
`COMPONENT_INPUT_MODEL.md` (фактическая модель ввода — что и как бот сейчас спрашивает),
`handlers/generation.py` и `services/generation_service.py` (порядок шагов, `CONTENT_MODULES`).

Документ не проектирует новую архитектуру и не меняет модель данных — это справочник для будущего UI поверх текущего поведения.

---

## Общие правила (действуют для всех компонентов ниже)

1. **Превью.** Для каждого компонента менеджеру нужно показывать его существующее превью из `mail_project/catalog.html` (строка с `letteros-element="<Название>"` внутри блока нужного модуля). Новые превью не создаются.
2. **Изображения не заполняются менеджером ни для одного компонента.** Если у компонента в `manifest.json` есть `variables[].type == "image"` — в таблицах ниже это отмечено строкой `Изображения: есть, не заполняются на этапе выбора компонента.` После генерации на месте картинки — жёлтый SVG-плейсхолдер; загрузка реального изображения происходит отдельно, вне бота.
3. **Ссылки (URL) не запрашиваются никогда**, даже когда в компоненте есть кнопка/CTA. Менеджер вводит только текст кнопки; сама ссылка в письме остаётся `href="#"` (кроме нескольких компонентов подвала/соцсетей, где ссылка зашита заранее и не связана с вводом текста).
4. **Число полей = число строк `sample_text` в `manifest.json`** для этого элемента. Бот сейчас не подписывает поля — просто просит «N строк, каждая с новой строки» и режет ввод по `\n`. Названия полей ниже — это то, что нужно **добавить** в будущий UI (они не выводятся ботом сегодня).
5. **Порядок полей = порядок появления в HTML-образце компонента** (проверено по `letteros-hide`-меткам в `catalog.html`, где они есть).
6. Модули **Шапки** и **Подвалы** (Header/Footer) и **Баннеры**, выбранные на отдельном шаге «Hero» — текст у менеджера не запрашивают вообще, даже если у них есть `sample_text`. Это отдельно оговорено в соответствующих разделах.
7. Модуль **Мероприятия** есть в каталоге компонентов, но **недоступен для выбора** в текущем Generation-flow бота (`CONTENT_MODULES` в `services/generation_service.py` его не включает — эти компоненты предназначены для отдельного трека Schedule v1). Указан в конце справочника только для полноты, без разбора полей.

## 2. Баннеры (используется в двух ролях — важно не перепутать)

Модуль «Баннеры» в боте задействован **дважды**:

- **Шаг «Hero»** (обязательный, один раз на письмо) — менеджер выбирает элемент модуля «Баннеры», но **текст не запрашивается вообще**. В письмо попадает библиотечный placeholder-текст (проверено на реальной сборке — плейсхолдеры остаются дословно).
- **Шаг «Контентные компоненты»** (цикл, если менеджер отдельно выбрал модуль «Баннеры» в списке контентных модулей) — для того же элемента текст **запрашивается** обычным образом (N строк по `sample_text`).

Поэтому таблица ниже с полями относится **только к случаю, когда «Баннеры» выбраны как контентный компонент**. Если это шаг Hero — просто показать превью и дать выбрать, без формы.

| Вариант 1, 2, 3, 4, 8 | 1. Заголовок · 2. Текст кнопки | Крупный заголовок баннера; надпись на кнопке |
| Вариант 5, 6, 7 | 1. Заголовок · 2. Описание · 3. Текст кнопки | Заголовок; поясняющий абзац под заголовком; надпись на кнопке |

Изображения: есть почти у всех вариантов (фоновые картинки блока), не заполняются на этапе выбора компонента.

Однозначно определить по коду и каталогу, задумано ли так (компонент предполагает вручную дорабатывать HTML после генерации) или это несостыковка в самой библиотеке компонентов, нельзя — нужно уточнение у владельца библиотеки компонентов.
