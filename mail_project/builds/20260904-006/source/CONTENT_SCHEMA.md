# CONTENT_SCHEMA.md

## Назначение

Документ описывает структуру входных данных, необходимых для генерации письма. Он определяет только содержимое блоков, без привязки к HTML, компонентам или визуальному оформлению.

---

# Hero

## Обязательные поля

- `title`
- `subtitle`
- `image`

## Необязательные поля

Нет.

## Допустимые значения

- `title` — строка.
- `subtitle` — строка.
- `image` — URL изображения или идентификатор изображения в используемой системе хранения.

## Ограничения

- используется один раз;
- открывает письмо;
- все поля обязательны.

## Пример

```yaml
hero:
  title: "Архитектура Москвы, которую редко замечают"
  subtitle: "Главные события ближайших недель"
  image: "https://..."
```

# Intro

## Обязательные поля

- `text`

## Необязательные поля

Нет.

## Допустимые значения

- `text` — строка.

## Ограничения

- используется один раз;
- представляет собой короткое вступление;
- не заменяет описание карточек.

## Пример

```yaml
intro:
  text: "Собрали самые интересные экскурсии, лекции и новые материалы недели."
```

# Card

## Обязательные поля

- `title`
- `text`
- `image`
- `cta`
- `link`

## Необязательные поля

Нет.

## Допустимые значения

- `title` — строка.
- `text` — строка.
- `image` — URL изображения.
- `cta` — строка.
- `link` — абсолютный URL.

## Ограничения

- одна карточка описывает один материал;
- каждая карточка должна содержать собственную ссылку;
- CTA относится только к своей карточке;
- допускается любое количество карточек.

## Пример

```yaml
cards:
  - title: "Экскурсия по Электрозаводу"
    text: "История одного из самых необычных промышленных комплексов Москвы."
    image: "https://..."
    cta: "Купить билет"
    link: "https://..."
```

# Schedule

## Обязательные поля

Для каждого события:

- `date`
- `time`
- `title`
- `description`
- `cta`

## Необязательные поля

Нет.

## Допустимые значения

- `date` — дата.
- `time` — время.
- `title` — строка.
- `description` — строка.
- `cta` — строка.

## Ограничения

- блок используется только при наличии расписания;
- содержит список событий;
- каждое событие имеет одинаковую структуру.

## Пример

```yaml
schedule:
  - date: "2026-09-18"
    time: "19:00"
    title: "Лекция"
    description: "История промышленной архитектуры."
    cta: "Записаться"
```

# Footer

## Обязательные поля

- `contacts`
- `social_links`
- `unsubscribe`

## Необязательные поля

Нет.

## Допустимые значения

### contacts

Строка или структурированный объект с контактной информацией.

### social_links

Список ссылок.

### unsubscribe

URL.

## Ограничения

- используется один раз;
- завершает письмо.

## Пример

```yaml
footer:
  contacts: "info@example.org"
  social_links:
    - https://t.me/example
    - https://vk.com/example
  unsubscribe: https://example.org/unsubscribe
```

# Минимальный набор данных от SMM

Для генерации письма необходимо предоставить:

```yaml
hero:
  title:
  subtitle:
  image:

intro:
  text:

cards:
  - title:
    text:
    image:
    cta:
    link:

footer:
  contacts:
  social_links:
  unsubscribe:
```

Если письмо содержит расписание мероприятий, дополнительно передается:

```yaml
schedule:
  - date:
    time:
    title:
    description:
    cta:
```

При отсутствии расписания блок `schedule` не передается.

# Image requirements

## Назначение

Описывает данные, необходимые для подготовки иллюстраций к письму.

## Поля

- `purpose` — назначение изображения / блок письма.
- `source` — исходное изображение или ссылка на него, если предоставлена.
- `format` — требуемый формат файла.
- `width` — требуемая ширина.
- `height` — требуемая высота.
- `aspect_ratio` — требуемое соотношение сторон.

## Ограничения

- Требования формируются только для изображений, которые используются в конкретном письме.
- Размеры и формат определяются существующим HTML-компонентом.
- Если для компонента технические требования к изображению не определены, они не должны придумыватьcя.

## Пример

~~~yaml
images:
  - purpose: "Hero — главное изображение выпуска"
    source:
    format: "jpg"
    width:
    height:
    aspect_ratio:
~~~
