# EVENTS_RULES.md

## Назначение

Документ определяет обработку выгрузки мероприятий для подготовки файла `SCHEDULE.txt`.

Входной файл — актуальная выгрузка событий текущего выпуска.

Постоянный справочник `tour_links.csv` используется для определения базовой ссылки тура.

---

## 1. Поля выгрузки

Используются:

- `ID события` — идентификатор конкретного события;
- `ID тура` — идентификатор тура;
- `Частная` — признак частного мероприятия;
- `Дата` — дата и время события;
- `Статус` — статус события;
- `Название` — название события;
- `Всего билетов` — общее количество билетов;
- `Осталось` — количество доступных билетов;
- `Филиал` — подразделение.

---

## 2. Отбор событий

В расписание включаются события, одновременно удовлетворяющие условиям:

1. `Статус` = `Active`;
2. в поле `Частная` нет значения `Ч`;
3. `Осталось / Всего билетов > 0.5`;
4. указаны `ID события`, `ID тура`, дата, время и название.

Если `Всего билетов` равно 0 или данных для расчёта доступности нет, событие не включается.

---

## 3. Повторяющиеся события

Каждая строка выгрузки — отдельное событие конкретной даты и времени.

Если один `ID тура` встречается несколько раз с разными датами или временем, каждое событие обрабатывается отдельно.

---

## 4. Лимит событий

На одну календарную дату включается максимум 20 событий.

Если после основных фильтров на дату прошло больше 20 событий:

1. выбрать 20 событий с максимальным количеством доступных билетов;
2. при одинаковом количестве доступных билетов использовать время начала как дополнительный критерий;
3. после отбора отсортировать выбранные события по времени начала.

Лимит применяется отдельно к каждой календарной дате.

---

## 5. Порядок

Даты расположить по возрастанию.

Внутри каждой даты события расположить по времени начала по возрастанию.

Для каждой календарной даты создать отдельную секцию в `SCHEDULE.txt`.

Если в указанном периоде на дату нет событий, прошедших фильтры, эту дату не включать.

---

## 6. Ссылки

Для каждого события сформировать ссылку на конкретное событие.

### Базовая ссылка

Найти `ID тура` в `tour_links.csv`.

Если запись найдена, использовать значение поля `Ссылка` как базовый URL тура.

Если запись не найдена, использовать:

`https://engineer-history.ru/tour/{ID тура}`

Название мероприятия не использовать для сопоставления с `tour_links.csv`.

### Ссылка на конкретное событие

К базовому URL добавить параметры конкретного события:

- дату события в `startDate` в формате `YYYY-MM-DD`;
- `event_id` из `ID события`;
- `utm_source` подразделения.

Для значения `Филиал`:

- `2` — МГИ → `utm_source=emailmgi`
- `3` — ПГИ → `utm_source=mail_pgi`
- `4` — КГИ → `utm_source=email_kgi`

Другие значения `Филиал` в этом формате расписания не обрабатываются.

Если URL уже содержит UTM-параметры, не дублировать их.

Итоговая ссылка должна вести на конкретное событие.

---

## 7. Ошибки данных

Если отсутствует `ID тура`, событие не включать.

Если отсутствует `ID события`, событие не включать.

Если отсутствуют дата, время или название, событие не включать.

---

## 8. Ошибки входного файла

Если файл невозможно прочитать, вывести только:

Не могу прочитать файл.

Если файл прочитан, но его содержимое не соответствует структуре выгрузки, вывести только:

Содержимое не соответствует полям выгрузки.

Технические причины ошибки, описание процесса чтения файла и другие пояснения не выводить.

---

## 9. Формат SCHEDULE.txt

Результат обработки всегда выдавать как содержимое файла `SCHEDULE.txt`.

Формат:

```text
SCHEDULE

DATE: DD.MM.YYYY

EVENT
event_id: <ID события>
tour_id: <ID тура>
time: HH:MM
title: <Название>
link: <итоговая ссылка>

EVENT
event_id: <ID события>
tour_id: <ID тура>
time: HH:MM
title: <Название>
link: <итоговая ссылка>

DATE: DD.MM.YYYY

EVENT
event_id: <ID события>
tour_id: <ID тура>
time: HH:MM
title: <Название>
link: <итоговая ссылка>
```

Правила формата:

- каждая дата начинается с `DATE:`;
- каждое событие начинается с `EVENT`;
- одно событие содержит ровно один набор полей `event_id`, `tour_id`, `time`, `title`, `link`;
- события внутри даты идут по времени;
- даты идут по календарному порядку;
- в файл включаются только события, прошедшие отбор;
- пустые даты не включаются;
- дополнительных описаний, комментариев и рекомендаций в `SCHEDULE.txt` не добавлять.

`SCHEDULE.txt` является готовым источником данных для блока Schedule на этапе сборки HTML.
