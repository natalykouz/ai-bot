# COMPONENT_SMM_FIELD_MAPPING.md

Mapping «модуль → компонент → одно поле, которое оставляем для ввода СММ» —
для каждого контентного компонента выбран один текстовый слот, который лучше
всего соответствует идее «заголовок/основная мысль блока».

Источники (актуальное состояние): `mail_project/COMPONENT_UI.md`,
`mail_project/manifest.json`. Документ не меняет модель данных, код или
поведение бота — справочник для будущего сокращения формы ввода до одного поля.

Область: только модули, реально доступные в текущем Generation-flow
(`CONTENT_MODULES` в `services/generation_service.py`). Шапки/Подвалы/Hero-Баннеры
не входят — текст у СММ для них не запрашивается вообще. «Мероприятия»
исключён — недоступен в `CONTENT_MODULES` (трек Schedule v1).

Там, где у компонента несколько текстовых полей, выбрано семантически ближайшее
к «заголовку» (обычно поле «Заголовок»). Там, где несколько полей параллельны
и явного «заголовка» нет (два тега, два блока в ряд, два автора, две карточки) —
выбрано первое по порядку чтения (слева/сверху); это отмечено отдельно.
